# Unreal 美術交接規格（準備版）

## 現階段

2026-10-18 使用者決定開始以 UE5 開發遊戲，使用既有 Blender 模型；先建立第三人稱小鎮行走原型，起步清單見 [Unreal/README.md](../Unreal/README.md)。不再等待整套素材建模完成。現有資產尚未在 UE 測試，以下規格作為逐項匯入與驗收依據。

目前包內 FBX 沿用既有幾何交接匯出，尚未逐一轉成最終 Unreal Static Mesh 套件。不要將整間鋪子數百個零件直接視為已最佳化遊戲資產。

## 尺度與原點

- Blender 原檔採 1 單位 = 1 公尺。
- Unreal 的預設長度單位是公分，匯入後先使用 `Calibration/UnitCube_1m.fbx` 核對是否為 100 × 100 × 100 公分；不應任意靠縮放猜尺寸。[Epic 官方匯入說明](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-static-meshes-in-unreal-engine)
- 民宅主牆範圍 7.2 × 5.2 公尺；鐵匠鋪地基 6.8 × 5.6 公尺，作為次要尺度核對。
- 各個最終獨立資產的原點放在底部或實際操作軸心。現在的場景組合與部分道具仍使用組合座標，需要另行整理。

## 拆件與檔名

- 靜態網格：`SM_類別_名稱_變體`；例如 `SM_Prop_Anvil_A`。
- 材質：`M_名稱`；實例：`MI_名稱_變體`；貼圖：`T_名稱_BaseColor` 等。
- 門、箱蓋、可裝備武器保留獨立物件；不能為了減少物件數而把活動部位與整棟建築合併。
- 靜態屋頂、牆體等依使用頻率與效能需求合併。源檔保留分件版本。

## 材質與 UV

目前木紋、石材等多為 Blender 程序材質。FBX 基本色不是烘焙貼圖；必須補做 UV，將顏色、粗糙度、法線等烘焙或在 Unreal 重建材質。

人物、近景武器、建築與植被的貼圖需求不同，先完成一件代表資產的交接驗證，再定各類解析度與預算。不要先把全部資產固定為高解析度貼圖。

## 碰撞與效能

自訂凸碰撞可使用 `UCX_網格名稱_編號` 等 Unreal 約定，名稱必須對應真正匯出的網格。碰撞形狀應維持簡單，門洞與通道保持可通行。[Epic FBX Static Mesh Pipeline](https://dev.epicgames.com/documentation/unreal-engine/fbx-static-mesh-pipeline-in-unreal-engine?lang=en-US)

目前尚未製作這些碰撞網格，也尚未決定 LOD／Nanite 的分配。迎客松針葉較多，應優先做植被效能測試；最終技術選擇需要配合目標平台、引擎版本與實際畫面驗證。

## 驗收勾選

- [ ] 公分尺度、正面朝向與原點正確。
- [ ] UV、法線、背面顯示與材質正確。
- [ ] 門洞、階梯和道路可供角色通過。
- [ ] 互動部位能獨立控制，骨架／動畫符合專案規格。
- [ ] 碰撞與效能符合實際場景需求。

上述項目尚未通過前，素材庫維持「外觀原型／待 UE 驗證」狀態。
